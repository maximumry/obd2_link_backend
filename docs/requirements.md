# 要件定義

## 目的

OBD2で取得した走行データを保存し、iPhoneで1回の走行ごとに振り返れるようにする。

## 対象ユーザー

自分の車の走行を記録・確認したい個人。1アカウントにつき記録端末1台を利用する。

## 機能要件

| 機能 | 内容 |
| --- | --- |
| アカウント管理 | メールで登録・ログイン、認証はパスキーのみ、表示名の変更、ログアウト、パスワード再設定、退会 |
| 端末管理 | 記録端末の登録、送信用トークンの発行・再発行 |
| データ保存 | 走行単位で計測値を受信・保存し、再送時の重複を防ぐ |
| 走行一覧 | 自分の走行を開始日時の新しい順に表示する |
| 走行詳細 | 開始・終了日時、走行時間、車速・回転数の時系列データを取得する |
| データ削除 | 走行データを削除する。退会時はアカウントと関連データを削除する |

### 画面構成

| 画面 | 内容 |
| --- | --- |
| 走行ライブラリ | 大きな見出し、右上のプロフィール、走行一覧への入口、最近の走行カード |
| 走行一覧 | 開始日時・走行時間・終了状態を表示し、選択すると詳細へ移動 |
| 走行詳細 | 走行概要、車速・回転数のグラフ、削除操作 |
| アカウント | プロフィール、端末設定、ログアウト、退会 |

iPhone側は黒背景・アクセント色・カードを使ったレイアウトとする。

### データの扱い

- 走行開始から終了までを1走行とし、記録端末からHTTPSで送信する。
- 車速・回転数を基本とし、スロットル開度・温度・GPS情報も任意で保存する。
- 取得できない値は`null`とする。
- 終了通知がない走行は「未終了」とし、最終受信日時を表示する。
- 走行時間は終了日時−開始日時で求め、未終了の場合は`null`とする。

## 非機能要件

- 認証と所有者確認を行い、本人のデータだけを操作できること。
- 本番通信はHTTPSとし、パスワード・トークン・計測値をログに出さないこと。
- 日時はUTCで保存・出力し、iPhone側でローカル時刻に変換すること。
- 一覧は最大100走行、計測値は最大1,000件／ページとすること。
- 受信は最大1,000件・1MiB／リクエストとし、不正なデータは保存しないこと。
- 単一アプリ・単一DBで運用し、DBは日次バックアップ・7日保持とすること。

## 対象外

複数車両・端末の管理、走行の共有、検索、通知、課金、リアルタイム配信、地図表示、距離・燃費・運転スコアの算出、故障診断、iPhoneアプリ・記録端末自体の実装。
